# DSH 屏幕录制器项目章程 (DSH Screen Recorder Constitution)

## Core Principles

### I. 平台承诺: Windows 10 及以上

应用 MUST 在 Windows 10 及更高版本(包括 Windows 11)上正常运行。
所有运行时依赖 MUST 在受支持的系统版本上可用;引入新依赖前 MUST 验证其最低系统要求。

理由: 明确目标平台边界,避免为不受支持的旧系统付出兼容成本,同时保证核心用户群的可用性。

### II. 三种录制模式

录屏功能 MUST 支持三种模式: 全屏、选定区域、指定应用窗口。
每次录制开始前 MUST 由用户显式选择其中一种模式;同一时间只允许一个录制会话。
「选定区域」模式的边界 MUST 可配置;「指定应用窗口」模式 MUST 以具体应用窗口为目标,捕获范围跟随该窗口。

理由: 三模式并存是产品核心需求,模式选择流程必须先于录制开始。

### III. MP4 输出

每次录制结束 MUST 生成一个 MP4 格式的视频文件。
输出文件 MUST 使用符合标准的 MP4 封装,并可由常见播放器直接播放。
无法生成有效 MP4 时 MUST 明确告知用户失败原因,不得静默丢弃录制内容。

理由: MP4 是用户指定的唯一交付格式,产出物有效性是功能完成的判定标准。

### IV. 托盘优先交互

应用启动后 MUST 默认最小化到系统托盘,不占用前台窗口。
右键点击托盘图标 MUST 弹出菜单,至少包含「录屏」与「设置」两个选项。
点击「录屏」后 MUST 展示三种模式供用户选择,并提供「开始」按钮以开始录制。
录制过程中应用与托盘菜单 MUST 保持可响应。

理由: 托盘常驻是用户指定的默认交互形态,所有入口都必须从托盘可达。

### V. 用户可配置

设置界面 MUST 提供录制区域范围与录屏文件存储位置的配置项。
用户修改的设置 MUST 持久化保存,并在下次启动与下次录制时生效。
存储位置 MUST 提供合理默认值且允许用户更改。

理由: 用户明确要求设置能力;配置丢失或不生效会直接破坏录屏产出与用户体验。

## 技术约束与质量要求 (Technical Constraints & Quality Requirements)

- 录制结束或应用退出时 MUST 完成 MP4 封装;异常中断时 MUST 尽力修复输出文件,确保已生成内容可播放或明确报告损坏。
- 三种模式的捕获实现 MUST 与设置中的区域范围配置保持一致。
- 录制 MUST 控制对系统性能的影响,保证录制期间目标应用保持可用。
- 全部功能 MUST 在 Windows 10 与 Windows 11 上分别通过验证。
- 章程未覆盖的产品细节(如音频、快捷键、编码参数)MUST 先经规范工作流澄清,再进入实现。

## 开发流程与质量门禁 (Development Workflow & Quality Gates)

- 采用 Spec-Driven Development: 每个功能 MUST 依次经过 specify → plan → tasks → implement 流程。
- 任何实现 MUST 可追溯到 spec.md / plan.md / tasks.md 中的条目。
- 验收标准 MUST 至少覆盖: 三种模式均可完成录制、输出为可播放 MP4、托盘菜单交互完整、设置持久化生效。
- 交付前 MUST 在 Windows 10 与 Windows 11 环境各完成一次验证。

## Governance

- 本章程是项目治理的最高准则,优先级高于其他任何实践;与章程冲突的实现 MUST 修正,或先按修订流程变更章程。
- 修订流程: 任何原则变更 MUST 通过 /speckit-constitution 工作流完成,并记录版本变更与理由。
- 版本策略: 采用语义化版本。MAJOR = 删除或重新定义原则(向后不兼容);MINOR = 新增原则或章节;PATCH = 措辞澄清与非语义修订。
- 合规审查: 每次制定规范(plan)与实施(implement)前 MUST 对照本章程核验一致性。
- 运行时开发指导: 以 .specify 工作流产物(spec.md / plan.md / tasks.md)为开发的事实来源。
